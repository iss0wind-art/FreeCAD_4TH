## II. 박제 #2 — SLAB 라벨 시스템 (도면 직독)

### PKG 평면도 SLAB 라벨 (1197건, 52 unique)
```
S10 (138), S12 (93), S3 (92), S13 (89), S2 (86), S1 (68),
S11 (67), S4 (59), S5 (54), S8 (47), ...
```
→ `S` + 1~2자리 숫자 = SLAB 단면 ID

### SLAB 일람표 라벨 (1132건, 22 unique)
```
D (579!), 10 (154), 200 (85), 150 (50), 300 (41), C (36),
13 (30), 250 (30), 400 (24), 100 (21), ...
```

→ 단일 알파벳 D/C = 단면 마커, 숫자 = 두께(mm) 또는 철근 직경

### 공통 라벨 = **0개**
두 시스템은 완전히 별개. 매칭 알고리즘이 영역 분할로도 풀리지 않을 가능성.
**해법 후보**: 일람표 도면 자체에서 SLAB ID(S1~S13) 텍스트를 다른 위치(타이틀)에서 추출 필요.

### 진단 재정의
박제 #3의 "PKG 3시트 X축 1.4km 분산" 표현은 부정확. 실제는:
- **단일 영역(1.9km 폭)**에 모든 콘크리트 부재 집중
- 시트 분리가 문제가 아니라 **DONG들과의 좌표 정합**이 진짜 과제
- 검증된 오프셋(`DONG_B1F_DX=-126000`, `PKG_B1F_DX=-630000`)과
  미흡한 `TX_PKG=-448000`의 차이가 진짜 풀 문제

**해법 후보**: EV 직독은 PKG에서 무효 → 격자 라벨(Y1~Yn = 동 번호 101~115) 매칭이 더 견고.

## IV. 박제 #4 — DONG_101 인코딩 (도면 직독)

### `ezdxf.readfile()` 인코딩 비교
| 인코딩 | 레이어 수 | 깨짐 수 | 깨짐% |
|--------|-----------|---------|-------|
| **cp949** (현행 기본) | 316 | **240** | **75.9%** |
| **utf-8** | 316 | 0 | 0.0% |
| **utf-8-sig** | 316 | 0 | 0.0% |
| mbcs | 316 | 240 | 75.9% |

### 진단 재정의
박제 #4는 "23 레이어 UNKNOWN"이라 했지만, 실제는 **240 레이어 UNKNOWN**. 그리고 원인은 한국어 인코딩 패턴 분석이 아니라 **`encoding` 파라미터 자체가 잘못됨**.

`scripts/extract_coords.py:263`에서 `encoding='cp949'`로 강제하고 있음.
**즉시 수정 가능한 1행 패치**.

```python
# 수정 전
doc_dong = ezdxf.readfile(DXF_DONG, encoding='cp949')
# 수정 후 (또는 인코딩 자동 시도)
doc_dong = ezdxf.readfile(DXF_DONG, encoding='utf-8')
```

검증: utf-8로 열면 `Defpoints`, `A-WALL-BRICK`, `A-PLAN-DIM300`, `A-FIN-1` 등 정상 출력.

## V. PKG 격자 라벨 재검토 (보너스)

`ev_detector.py`의 격자 정규식:
```python
_GRID_X1 = re.compile(r'^X\s*1$|^[Aa]\s*$|^①$', re.IGNORECASE)
```

### PKG 짧은 텍스트 패턴 분포 (3717건)
| 패턴 | 건수 |
|------|------|
| alpha_single (`A`, `B`...) | **3건** |
| alpha_multi (`AB`, `EV`...) | 14건 |
| digit_only (`1`, `100`...) | 46건 |
| **alpha_digit (`A1`, `S10`...)** | **1147건** |

### 짧은 텍스트 TOP 20
```
S10 (138), REG3 (127), S12 (93), S3 (92), S13 (89), -1EG3 (86),
S2 (86), REG2 (70), S1 (68), S11 (67), -1PG1 (66), RWG1 (64),
RPG1 (62), RPG3 (60), S4 (59), EC1 (54), S5 (54), -1WG1 (50),
AC1 (49), S8 (47)
```

### 의미
- 격자가 아니라 **부재 ID 라벨**이 압도적
- 격자 라벨 단독 레이어 없음 (`GRID|AXIS|축` 매칭 0건)
- 격자는 다른 레이어에 텍스트로 산재 → 정규식 강화로 추출 가능
- 패턴 후보:
  - `S` 시리즈: SLAB
  - `REG`, `PG`, `WG`: 보(Beam) — Roof Edge Girder, Pillar Girder, Wall Girder?
  - `EC`, `AC`: 기둥(Column) — End Column, Apt Column?

## VI. 끌로드 트랙 확정 방안

### 즉시 적용 가능한 수정 3건 (저비용 고이득)
1. **인코딩 패치** (박제 #4): `extract_coords.py`, `level_parser.py` 등에서
   `encoding='cp949'` → `encoding='utf-8'` 또는 자동 시도 fallback
2. **격자 정규식 확대** (박제 #1, 보너스):
   `S\d+`, `REG\d+`, `RWG\d+`, `EC\d+`, `AC\d+` 등 부재 ID 패턴 추가 → BEAM 라벨 매칭률 향상
3. **paperspace 무시** (박제 #3): paperspace는 빈 껍데기. 모델공간 단일 영역 가정으로 단순화

### 끌로드 팀 우선순위 트랙 결정
- **A안 (EV 직독)**: 데이터로 무효 확정. **기각**
- **B안 (검증/감사)**: 데이터로 박제 진단 자체의 부정확성을 발견. **계속 진행 가치 큼**
- **C안 (Phase 2 통합)**: 박제 해결 후 자연스럽게 진행. 보류

**확정**: **B안 = 진단 검증 + 즉시 수정 패치 트랙**.

다음 행동:
1. 인코딩 패치 PR (1행 수정으로 240 레이어 복원)
2. 격자/부재 정규식 확대 (BEAM NOLABEL 80% 의 일부 회수)
3. SLAB 일람표 진짜 매칭 키 도면 직독 (S1~S13이 일람표 어디에 있는지 추가 probe)

### 개팀장 트랙과의 관계
- 개팀장 트랙(베테랑 3인 페르소나)이 박제 4건 해결 중인 상태에서,
  끌로드 트랙은 **진단 자체의 정합성을 도면 데이터로 재검증**하는 견제 역할 수행
- 두 트랙의 산출물 비교 = 갑인자 사상의 정교화 검증
