# 도면 분석 패턴 라이브러리

다른 도면에서 같은 패턴 마주치면 본 파일 검색 → 즉시 인식·대응. 새 패턴 발견 시 즉시 누적 박제.

## A. 부재 표기 패턴

### A-1. 트랜스퍼 짝기둥 (Transfer Twin Column)
**식별 조건:**
- 단면 W > H (예: 1500×800)
- 지하 구간(B2~1F)에만 표기
- 1층 위에서 같은 위치 다른 코드(예: `1TC15`)로 단면 정상 복귀(W < H)
- 결번(같은 시리즈에서 일부 번호 빠짐) 동반 가능

**의미:** 지하주차장에서 상부 아파트 기둥열을 받기 위해 가로로 눕힌 짝기둥. 한국 아파트 전이 구간 전형.

**대응:** 정상 패턴. 이상치 아님. BOQ 산출 시 그대로 처리.

**최초 발견:** S30-471~491 101~112동 기둥리스트 / TC15·TC16 (2026-05-05)

---

### A-2. 벽기둥 / 코어 전단벽 조각 (Wall Pier / Core Shear Wall)
**식별 조건:**
- 종횡비 ≥ 3.5 (예: 2700×700 = 3.86, 2400×600 = 4.00)
- 단면 1.5㎡ 이상 (일반 기둥의 3~4배)
- 타워형/대형 평면(예: 116동 같은 큰 동)에 다수
- "기둥 리스트"에 함께 부호화

**의미:** KBC 정의상 기둥 경계 또는 초과. 사실상 외곽·코어 전단벽 조각을 기둥 코드로 부호화한 한국 고층 관행.

**대응:** 기둥으로 처리하되 BOQ에서는 벽체로 분류해도 무방. 단면 검증 후 모델링.

**최초 발견:** S30-492~507 113~116동 기둥리스트 / TC51·53·71·73 (2026-05-05)

---

### A-3. 영역별 독립 코드 체계 (Region-Scoped Codes)
**식별 조건:**
- 같은 base 코드(C1, C2, TC1 등)가 다른 일람표에서 다른 단면·배근으로 정의
- 한쪽 일람표에 **층범위 prefix** 부착(예: `-2~-1C1`, `-1TC1`)
- 응력 환경 차이(지하 토압 vs 상부 자중)로 부재 사양도 다름

**의미:** 도면 작성자가 영역(지하 vs 동)별 독립 코드 체계를 의도. 우연한 중복 아님.

**대응:** PK 정책 = **영역 코드 + base** (예: `BSMT_-2~-1_C1`, `DONG101~112_C1`).

**최초 발견:** C1·C2·TC1·TC2 (2026-05-05)

---

### A-4. 결번 = 해당 층 부재 부재(不在)
**식별 조건:**
- 시퀀스에서 일부 번호 빠짐 (예: TC1~16 + TC19, TC22 + TC17·18·20·21 결번)
- 다른 일람표에서는 해당 번호 존재

**의미:** 그 부재가 그 영역·층에서 사용 안 됨. 도면 누락 아님.

**대응:** 정상. 다른 일람표에서 추출.

**최초 발견:** S30-471 결번 → S30-492에 존재 (2026-05-05)

## B. DXF 구조 패턴

### B-1. 외부참조(XR) 레이어 봉인
**식별 조건:**
- 레이어 이름이 `XR<도면명>$0$<원래레이어>` 형식 (예: `XR101동기준층평면도(구조)$0$A-WALL-RC`)
- 모델스페이스에 직접 도형은 없고 외부참조로 관리

**대응:**
```python
if layer.endswith('A-WALL-RC') or 'A-WALL-RC' in layer:
    # 처리
```

**최초 발견:** 101동 free_test.dxf (2026-05-04)

---

### B-2. 중첩 블록 INSERT (Nested Blocks)
**식별 조건:**
- 모델스페이스에 INSERT 1~2개만, 안에 또 INSERT 있음
- `virtual_entities()` 한 번으로 안 풀림

**대응:**
```python
def iter_all(container, depth=0, max_depth=10):
    for e in container:
        if e.dxftype() == 'INSERT':
            yield from iter_all(list(e.virtual_entities()), depth+1, max_depth)
        else:
            yield e
```

**최초 발견:** 102_B1F.dxf, 새 블럭.dxf, 111.dxf (2026-05-05)

---

### B-3. OLE2FRAME 임베드 봉인
**식별 조건:**
- DXF 안에 `OLE2FRAME` 엔티티 다수 (수십~수백 개)
- 도면 텍스트는 표제·도면번호만 있고 본 데이터 없음
- 파일 크기 매우 큼 (200MB+) 비례

**의미:** Excel·Word·내장 도면 객체로 데이터 봉인 → DXF로 추출 불가

**대응:**
- A. 사용자에게 Excel/CSV 별 제공 청 (가장 빠름)
- B. AutoCAD GUI에서 OLE EXPLODE 후 DXF 재변환
- C. PDF 변환 후 OCR (정확도 낮음)

**최초 발견:** S30-411 벽체 일람표 261MB (2026-05-05)

---

### B-4. 한글 인코딩 cp949
**식별 조건:**
- ezdxf 기본 utf-8로 읽으면 한글 깨짐 또는 surrogate 오류
- 한국 도면 거의 100%

**대응:**
```python
doc = ezdxf.readfile(path, encoding='cp949')
sys.stdout.reconfigure(encoding='utf-8', errors='replace')
```

---

### B-5. 슬라브 외곽선 자체교차
**식별 조건:**
- 슬라브 폴리라인 조립 후 폐합되나 FreeCAD Face 생성 시 `BRepAdaptor_Curve::No geometry` 오류
- 점이 많은 외곽선(50점 이상) 흔함

**대응:**
```python
poly = ShPoly(coords)
if not poly.is_valid:
    fixed = make_valid(poly)
    if fixed.geom_type == 'MultiPolygon':
        poly = max(fixed.geoms, key=lambda p: p.area)
```

**최초 발견:** 101동 free_test.dxf 슬라브 53점 외곽선 (2026-05-04)

## C. 일람표 형식 패턴

### C-1. 기둥 단면: 괄호 있음
**형식:** `( 600 x 1200 )` 또는 `(600x1200)`
**정규식:** `\(\s*(\d{3,4})\s*[xX]\s*(\d{3,4})\s*\)`

### C-2. 보 단면: 괄호 없음
**형식:** `500 x 900`, `600 x 600`
**정규식:** `\(?\s*(\d{3,4})\s*[xX×]\s*(\d{3,4})\s*\)?`

### C-3. 주근 표기
**형식:** `20-D25` (개수-직경)
**정규식:** `^(\d{1,2})-(D\d{2})$`

### C-4. 후프(스터럽) 표기
**형식:** `D10@150` (직경@간격)
**정규식:** `^(D\d{1,2})@(\d{2,3})$`
**특이:** 보 일람표에는 후프 별도 표기 안 됨 (D10@200 표준 일관 적용 추정)

### C-5. 보 양단 구분 표기
**형식:** `'A1 :        A3 :'` 형식
**의미:** 보 일람표만의 양단(좌·우) 부재 그룹화

## D. 부재 단위 변환 패턴

### D-1. 부재 영역 = 슬라브 영역
**식별 조건:**
- 슬라브 외곽선이 동(주거동) 영역만 그려짐
- 거더는 주차장 영역(슬라브 밖)에 위치

**대응:** 슬라브 폴리곤 클립으로 부재 필터링하면 거더 0개. 통합 도면 필요 (청 3 사안).

**최초 발견:** 102_B1F.dxf, 거더 Y<22000 / 슬라브 Y>36000 (2026-05-05)

---

### D-2. BEAM NAME 레이어 ≠ 보 본체
**식별 조건:**
- `00_BEAM NAME` 레이어에 작은 LINE 쌍 (200×1170mm 등)
- 보 본체가 아니라 보 이름표 박스

**대응:** 보 본체는 다른 레이어에서 추출 (`00_BEAM`, `00_(APT)BEAM` 등).

**최초 발견:** 101동 free_test.dxf (2026-05-04)

## E. 트림 / Boolean 패턴

### E-1. Boolean Fuse 자동 공제
**식별 조건:** 부재 솔리드 다수 → 거푸집 면적 산출
**대응:**
```python
fused = solids[0]
for s in solids[1:]:
    fused = fused.fuse(s)
# 외피 vertical_area + downward_area = 자동 공제 후 거푸집
```
**효과:** 거푸집 5%, 콘크리트 2.5% 자동 공제 (실측 비례)

## F. 좌표 기준점 (Origin Anchoring)

### F-1. E/V 코어 모서리 = 좌표 기준점 ★★★
**현업 노하우 (방부장 친전, 2026-05-05):**
> *"동의 경우 E/V는 꼭대기까지 변하지 않는 곳이라, 거기 모서리 중 하나를 기준점으로 잡는다.
> 도면에도 일부 표시가 되어있는 경우도 많다."*

**식별 조건:**
- 동(주거동) 도면에서 E/V(엘리베이터) 코어 위치
- 모든 층 도면에서 **위치·크기 변하지 않음** (옥상까지)
- 도면 내 텍스트 `'E/V'`, `'EV'`, `'엘리베이터'` 표기 가능

**적용 방법:**
1. 텍스트 `E/V` / `EV` 위치 검출
2. 그 주변 폐합 LWPOLYLINE 또는 LINE 사각형 영역 검출 (코어 본체)
3. 사각형 한 모서리(예: 좌하단)를 (0,0,0)으로 지정
4. 모든 부재 좌표를 이 기준점 대비 상대 좌표로 변환
5. 모든 층 도면이 같은 (0,0,0)으로 정렬됨

**효과:**
- 9 도엽 합본 도면(예: `S30-021~029-102동 구조평면도`)에서 자동 적층 정확
- 도엽 박스 격자 배치 무관, 본체 부재 위치 정렬

**최초 박제:** 2026-05-05 방부장 친전

### F-2. 도엽 본체 BoundBox 자동 검출 (대안)
E/V 검출 실패 시 폴백:
- 도엽 박스 안 부재 LINE/LWPOLYLINE의 BoundBox 계산
- 도면틀(외곽 큰 사각형) 제외 후 본체만
- 본체 BoundBox 좌하단을 (0,0)으로
