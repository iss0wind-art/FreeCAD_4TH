## ☑ Pre-flight — 하드웨어 실측 (10분)

| # | 행동 | 합격선 | 불합격 시 |
|---|------|--------|-----------|
| P1 | `nvidia-smi` | RTX 3050 / 드라이버 / **8192MiB** 표시 | 미표시 → GPU 드라이버 재설치 (이후 전부 보류) |
| P2 | `nvidia-smi` → CUDA Version 확인 | **12.x** 이상 | 11.x 이하 → 드라이버 업데이트 권장 |
| P3 | `wmic OS get FreePhysicalMemory` (또는 작업관리자) | 가용 RAM **16GB+** | 부족 → 백그라운드 앱 종료 |
| P4 | 디스크 여유 (모델 저장 드라이브) | **20GB+** (모델+위키+볼트) | 부족 → 정리 |

**⚠ Hyper-V/WSL2 분기 — 가장 중요**

```
ollama 를 "Windows 네이티브"로 설치하면 Hyper-V 네트워크 어댑터는 GPU 인식과 무관하다.
ollama 를 "WSL2 안"에서 돌리면 GPU 패스스루 설정이 선행돼야 한다.
→ 네이티브 설치를 기본으로 한다 (분기 회피).
```

| B2 | `ollama pull qwen2.5:7b` | `success` (≈4.7GB Q4) | 실패 → 네트워크/디스크 확인 |

| B4 | **(핵심)** 응답 직후 새 창에서 `ollama ps` | **`100% GPU`** 표시 | `CPU`/분할 → ★아래 GPU 분기 |
| B5 | `ollama run qwen2.5:7b --verbose "..."` → `eval rate` 확인 | ★아래 속도 판정 | — |

### ★ 토큰 속도 판정 (B5의 eval rate)

| 속도 | 판정 | 조치 |
|------|------|------|
| **≥20 tok/s** | 우수 ✅ | 단계 1 진입 가능 |
| 10~20 tok/s | 합격 🟡 | 진행하되 GPU 점유 재확인 |
| **<10 tok/s** | 불합격 ❌ | CPU 폴백 의심 → B4 `ollama ps` 다시 봐라 |

### ★ GPU 분기 (B4가 CPU로 나올 때)

1. `ollama ps`가 `CPU`면 → Ollama가 GPU를 못 잡은 것 (속도 10배 저하 원인)
2. 작업관리자 → 성능 → GPU 탭에서 추론 중 GPU 사용률 확인
3. WSL2 안에서 돌고 있지 않은지 확인 → 네이티브로 재설치 (Pre-flight 분기)
4. 그래도 안 되면 → **여기서 멈추고 본영/방부장 보고**. 두뇌가 죽으면 주니어 전체가 보류다.
